VPN-UI は、マルチプロトコル VPN 管理パネルです。 **v1.0.0 は、このフォークの最初の安定リリースです。** ソース、インストーラー、およびアップデートは、[Sir-MmD/vpn-ui](https://github.com/admin6501/vpn-ui) および [3X-UI](https://github.com/Sir-MmD/vpn-ui) に基づいて、[admin6501/vpn-ui](https://github.com/MHSanaei/3x-ui) から提供されます。

## 13の言語

パネル、サブスクリプション ブラウザ ページ、内蔵 Telegram ボット、共有 UI コントロールは、英語、ペルシア語、アラビア語、スペイン語、インドネシア語、日本語、ポルトガル語 (ブラジル)、ロシア語、トルコ語、ウクライナ語、ベトナム語、中国語 (簡体字)、中国語 (繁体字) をサポートしています。言語セレクターで Web 言語を選択します。 Telegram 設定でボット言語を構成します。ボットは、Telegram チャットごとに個別の自動設定ではなく、構成された言語を使用します。

Web リクエストは、同時パネルおよびサブスクリプションリクエストを含め、独自の言語を保持します。地域のバリエーションは、サポートされているロケールに解決されます。ダイアログ、カレンダー、ページネーションでは、選択した言語が使用されます。プロトコル識別子、構成キー、コマンド名、および診断出力は、元の構文を保持します。ターミナルのインストーラは英語を使用します。移行ウィザードではペルシア語と英語が提供されます。 [docs/TRANSLATIONS.md](docs/TRANSLATIONS.md) を参照してください。

## プロトコルとコア

| ランタイム | プロトコルと実装 |
| --- | --- |
| バンドルされた X 線 | VLESS, VMess, Trojan, Shadowsocks, Hysteria2, AnyTLS, TUIC, NaiveProxy, WireGuard |
| ポータブル VPN バックエンド | OpenVPN (TCP/UDP)、OpenConnect (ocserv)、L2TP、PPTP、SSTP、IKEv2 |
| カーネルトンネル | WireGuard (`wg-c`)、AmneziaWG (`awg`)、および GRE、サポートされている場合はオプションの IPsec または FOU |
| 内蔵リレー | MTProto プロキシとアカウントごとの認証を備えた SSH プロキシ |

IPsec はコア インストールで選択可能で、L2TP/IKEv2 の共有依存関係でもあります。必要な依存関係は、インストールされている別のコアがそれらを必要とする間も保持されます。カーネル WireGuard とネイティブ Xray WireGuard は異なる実装です。組み込みの SSH 機能は VPN トラフィックを転送します。ルートシェルは提供されません。

完全なバイナリには、ポータブル バックエンド、パッチ適用された Xray コア、ACME クライアント、および 6 つの地理データ ファイル (ベース、イラン、ロシアの geoip/geosite) が含まれています。 OS パッケージ、カーネル モジュール、カーネル ヘッダー、および DKMS は引き続きホスト要件です。 [コア] ページには、インストールの進行状況、不足している前提条件、および実際のサービス ステータスが表示されます。 IPsec が有効になっていない限り、プレーン GRE は暗号化されません。 PPTP はレガシー プロトコルです。 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) を参照してください。

## ユーザー、グループ、サブスクリプション

**ユーザー**で顧客を管理し、**受信**でインフラストラクチャを管理し、**グループ**で再利用可能な受信割り当てを管理します。 1 つのアカウントで、共有クォータとサブスクリプションを使用して、互換性のある複数の受信とロケーションを使用できます。グループを変更すると、アカウントの資格情報を置き換えることなく割り当てが更新されます。個々のメンバーシップの切り替えとグローバル アカウントの切り替えは分離されたままになります。

API フィールド名が `totalGB` であるにもかかわらず、トラフィック制限はバイト単位で保存されます。トラフィック制限がゼロのアカウントのトラフィックは無制限です。有効期限がゼロの場合は、期限が無制限であることを意味します。遅延開始プランは、最初の使用時に開始されます。概要の合計では、メンバーシップごとに 1 人のユーザーではなく、一意のアカウントの数がカウントされます。異なるアカウント間でサブスクリプション ID を共有すると、それらの構成が一緒に公開されます。アイデンティティを統合したり、個別の制限を 1 つの共有アカウント クォータに変換したりすることはありません。

バンドルされたコアは、新しい使用法をそのソース インバウンドに帰属させます。アカウント情報には、測定された株式と過去の未帰属残余が個別に表示されます。アップグレードすると、既存の使用状況が維持されます。古いアカウントのみのレコードは、履歴分割を再作成できません。外部プロキシ エンドポイントは、アカウント/構成のエクスポートで一貫して使用されます。 OpenVPN プロファイルと WireGuard ピア ファイルは、対応する構成ビューからダウンロードできます。

### 更新、トラフィックのリセット、フリーズ

**ユーザー → クライアントの 3 点メニュー → 更新** により、メンバーシップ全体で現在のアップロード/ダウンロードがクリアされ、今から全パッケージ期間が開始され、アカウントが有効になります。トラフィックのみ、時間のみ、組み合わせたプラン、および完全に無制限のプランがサポートされています。クォータ、パスワード、UUID、サブスクリプション ID、デバイス キー、ピア アドレス、および受信アクセスは変更されません。不明なレガシー期間では、日数を一度尋ねて記憶します。

**トラフィックのリセット** は、有効期限を再開したり、手動で無効にしたアカウントを有効にしたりせずに、現在の使用量をクリアします。 **凍結**は残りの日数を一時停止します。解凍すると残りが復元されます。更新では、代わりに録画されたパッケージの全期間が使用されます。生涯アカウンティングと累積ノードカウンターは保存されます。代表者の制限と障害のあるメンバーシップは引き続き適用されます。 [docs/CLIENT-RENEWAL.md](docs/CLIENT-RENEWAL.md) および [docs/PANEL-GUIDE.md](docs/PANEL-GUIDE.md) を参照してください。

### 速度とアクセス制限

ダウンロード/アップロードのオーバーライドは、KB/秒、MB/秒、または Mbps を受け入れます。空の場合は受信設定を継承します。ゼロは、その方向に無制限を意味します。ストレージは 1024 バイト KB/秒を使用しますが、Mbps は 10 進数のメガビットを意味します。 UI の MB/秒は 1024 ベースのバイトを使用します。**3 MB/s = 24 Mib/s ≈ 25.17 Mbps** に相当します。速度値は、正の場合は少なくとも 1 KB/秒に丸められます。

ソース IP の制限では、1 つの NAT の背後にある物理デバイスではなく、目に見えるアドレスがカウントされます。セッションとピアの制限はプロトコルによって異なります。 WireGuard/AmneziaWG は個別のデバイス構成を発行します。サポートされる制限は各形式に示されています。ノードのセッション/IP 制限は各ノードに対してローカルです。

## 管理者および代表者

初期管理者は、保護されたパネルの所有者です。管理者の役割とカスタム権限によって操作が決まります。グループ/インバウンド割り当てによって範囲が決まります。所有者に依存したデータベース、認証、実行可能操作は個別に保護されます。明示的なパネル設定許可により、テレグラム、LDAP、証明書、サービス設定を含む完全な許可設定ページが開きます。

新しい代表アカウントは、消費ベースの会計と範囲指定されたロールを使用します。既存のプリペイド アカウントは独自の請求ルールを保持します。更新、削除、および使用量のリセットの許可は別のものです。手動更新には、より狭い範囲での更新とリセットの両方の権限が必要です。所有権の譲渡では顧客の資格情報が保持され、対象となる所有者に制限されます。許可を使い果たした代表者には、設定された切断ポリシーが引き続き適用されます。

サインインしているすべてのアカウントは、**アカウント セキュリティ**で独自の認証システムを管理できます。登録には、現在のパスワードと有効なワンタイム コードが必要です。マネージャーは、代表者に 2 要素登録を要求できます。保留中の登録では、アカウントのセキュリティとログアウトのみが許可されます。シークレットとサブスクリプション リンクは資格情報として扱う必要があります。

## 複数の場所にあるノード

1 つの中央パネルが、アウトバウンドの検証済み HTTPS を介して専用のロケーション エージェントを管理します。ノードは 1 つのパネルとペアになります。エージェントを別のロケーション サーバーにインストールし、ノードの [コア] ダイアログで必要なコアを選択します。最初のエージェントのインストールでは、VPN コアはアクティブになりません。 **ノードと場所の管理** を使用してノード管理を委任します。代表者はこのインフラ補助金を受け取ることはできません。

エージェントのポーリングと表示される「ノード」ページは毎秒更新されます。ホスト診断は、通常は 5 秒ごとに個別に更新されます。スナップショットを変更しないと、クライアント テーブルの書き換えが回避されます。変更された構成により、影響を受けるコアが調整されます。コアのインストール/削除、ランタイム制御、構成編集では、継続的な進行状況と確認応答が表示されます。

アカウントは、複数の場所にわたって 1 つの中央クォータとサブスクリプションを保持します。承認された累積レポートは二重に請求されることはありません。変更は非同期的に伝播します。機内トラフィックと同時ロケーションにより、一時的に割り当てを超える場合があります。オンライン ノードのデータは 35 秒後に古くなります。 90 秒間管理リースを失うと、カウンタを保持したまま VPN データ プレーンが停止します。新しい有効なスナップショット復元サービス。 [docs/NODES.md](docs/NODES.md) および [docs/NODES.fa.md](docs/NODES.fa.md) を参照してください。

## システム要件

Linux amd64 (x86-64) または arm64 (aarch64)、root アクセス、Bash、および実行中の systemd システムが必要です。 Ubuntu 24.04 および Debian 12/13 が推奨される展開ターゲットです。ホストのネットワーク権限とプロトコル固有のモジュールは引き続き必要です。パネルのインストールが成功しても、すべてのディストリビューション、カーネル、または VPS 上のすべてのプロトコルが認定されるわけではありません。 [table.md](table.md) を参照してください。

標準のインストールディレクトリは`/opt/vpn-ui`です。インストールされた実行可能ファイルは、両方のアーキテクチャで互換性名 `/opt/vpn-ui/vpn-ui-amd64` を保持します。バンドルされたコア ファイル名は、実際のアーキテクチャに従います。ノードは `/opt/vpn-ui-node` と独自の systemd サービスを使用します。

## オンラインでインストールまたはアップデートする

```bash
curl -fsSL https://raw.githubusercontent.com/admin6501/vpn-ui/main/deploy.sh -o deploy.sh
sudo bash deploy.sh
```

同じコマンドは、データベースとログイン設定を保持したまま、既存の標準インストールを更新します。まずバックアップしてください。新規インストールでは、ランダムな認証情報、ポート、Web パスが出力されます。出力された HTTP/HTTPS スキームを含む正確な URL を開き、`0.0.0.0` などのリッスン アドレスをサーバーの到達可能なアドレスに置き換えます。新規インストールでは、TLS が設定されるまで HTTP を使用します。

既存のペアリングされたノードの場合は、そのインストーラーをダウンロードして実行します。メニューからインストール/アップデートを選択します。既存のペアリングとカウンターは保持されます。

```bash
curl -fsSL https://raw.githubusercontent.com/admin6501/vpn-ui/main/install-node.sh -o install-node.sh
sudo bash install-node.sh
```

新しいノードは、中央パネルで生成されたペアリング コマンドを使用する必要があります。ノード メニューには、ステータス、開始、停止、再起動、最近のログ、確認された削除も表示されます。 `--install` は、メニュー以外の直接更新パスを保持します。 [management-cli-plan.md](management-cli-plan.md) を参照してください。

## オフラインでのインストールとアップデート

アーキテクチャに一致するバイナリ `install-offline.sh` および `SHA256SUMS` を [安定版リリース](https://github.com/admin6501/vpn-ui/releases/tag/v1.0.0) からダウンロードします。これらをまとめて転送し、インストール前に利用可能なファイルを確認します。

```bash
sha256sum --ignore-missing -c SHA256SUMS
sudo bash install-offline.sh ./vpn-ui-amd64
# ARM64: sudo bash install-offline.sh ./vpn-ui-arm64
```

オプションの適切な前提条件の質問は、EOF を含めてデフォルトで **No** になります。いいえ、パネルのインストールはローカルに維持されます。はいには、到達可能な apt リポジトリが必要です。 apt エラーが報告され、ローカル インストールが続行されます。必要な OS パッケージとカーネル モジュールを個別にプレインストールまたは転送します。更新により、データベース、認証情報、TLS 設定が保存され、プライベート ロールバック バックアップが保持されます。

インストーラーは `VPNUI_OFFLINE=1` を記録し、パッケージの自動ダウンロード、パブリック IP ルックアップ、および地理データの更新を無効にします。 VPN トラフィックは引き続き機能します。手動アップデート、WARP および ACME の発行/更新には引き続きインターネットが必要です。オフライン ノードのインストールには、一致するノード バイナリと `install-node.sh` をそのペアリング オプションとともに使用します。 [docs/OFFLINE-INSTALL.md](docs/OFFLINE-INSTALL.md) を参照してください。

## PasarGuard バックアップの移行

まず互換性のある行先パネルを取り付けてください。 VPN アカウントと受信は空である必要があります。既存のパネルの Web/TLS 設定は保持されます。実行:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/admin6501/vpn-ui/main/migration/install.sh)
```

ペルシア語または英語を選択し、絶対バックアップ ZIP パスを指定します。移行パッケージには、別のパネル バイナリではなく、スクリプトと構成が含まれています。 Python 3 と解凍が必要です。オフライン変換の場合は、`vpn-ui-auto-migration.zip` を転送して抽出し、その `migrate.sh` をバックアップ パスで直接実行します。

サポートされているアカウント ID、管理者の所有権、グループ/割り当て、ホスト、パスワード ハッシュ、およびサブスクリプション互換性メタデータがインポートされます。以前の管理者パスワードを使用します。ハッシュでは平文のパスワードを明らかにすることはできません。 PasarGuard ノードはインポートされません。ドメイン/IP を変更するには、サブスクリプションのベース アドレスを更新し、エクスポートされたエンドポイントを確認する必要があります。変換された構成を確認し、実際に使用するプロトコルをテストします。 [migration/INSTALL-MIGRATION.fa.md](migration/INSTALL-MIGRATION.fa.md) を参照してください。

## ビルド、テスト、ドキュメント化

```bash
git clone --recurse-submodules https://github.com/admin6501/vpn-ui.git
cd vpn-ui
./build.sh --help
./build.sh
```

`go.mod` の Go ツールチェーンと固定されたサブモジュール/セキュリティ パッチを使用します。完全なリリースでは、コア、バックエンド、およびすべての地理データを構築する必要があります。スキップされたバンドルは開発バイナリを生成します。ビルドには、オンラインの依存関係、C ツールチェーン、および必要に応じて Docker を含むバックエンド ビルド ツールが必要です。 ACME には、クライアントがバンドルされている場合でもインターネットが必要です。

リリース ワークフローでは、サポートされている言語でのネイティブ アーキテクチャ、重点的なアカウンティングと権限の動作、実際の Xray/ノード データ パス、オフライン インストール/更新、およびブラウザの動作の両方を検証します。個別の Incus プロトコル/配布マトリックスには、準備された特権付き VM ホストとインターネットが必要です。その存在は、すべてのマトリックス エントリが再実行されたという証拠ではありません。 [test_unit/README.md](test_unit/README.md)、[docs/INDEX.md](docs/INDEX.md)、[api-reference.md](api-reference.md)、および [.github/workflows/release.yml](.github/workflows/release.yml) を参照してください。

## Telegram 販売ボット

Ubuntu または Debian 向けに、ウォレット付きの VPN-UI 販売・サービス管理用 Telegram ボットを用意しています。新規インストールはローカルデータベースを作成し、Cloudflare のデータは移行しません。[ボットの手順](docs/TELEGRAM-SALES-BOT.md)。

独立した販売ボットの表示言語はペルシア語です。複数パネル、カテゴリ、残量を引き継ぐ更新、任意の移行をサポートします。[API](docs/REPRESENTATIVE-BOT-API.fa.md)・[移行ガイド](docs/BOT-LOCATION-MIGRATION.fa.md)。

```bash
curl -fsSL https://raw.githubusercontent.com/admin6501/vpn-ui/main/scripts/install-telegram-bot.sh -o install-telegram-bot.sh && sudo bash install-telegram-bot.sh
```
