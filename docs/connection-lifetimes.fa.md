# مهلت اتصال‌ها در هستهٔ فعلی

**نسخهٔ پایدار v1.0.0:** تنظیمات زمان اتصال را از حجم/روز اشتراک جدا در نظر بگیرید.
تمدید یا ریست ترافیک، timeout شبکه را تغییر نمی‌دهد. مسیر copy بومی ممکن است مهلت داخلی متفاوتی
از policy عمومی داشته باشد؛ پیش‌فرض‌های زیر به معنی تضمین زمان قطع یکسان برای همهٔ پروتکل‌ها نیستند.
نتایج loopback با آزمون واقعی اینترنت و تانل یکسان نیست. [معماری](ARCHITECTURE.md).

هنگام ساخت کانفیگ Xray، مقادیر زیر فقط برای فیلدهای بدون مقدار اضافه می‌شوند:

| تنظیم                                   | پیش‌فرض           |
| --------------------------------------- | ----------------- |
| `policy.levels.*.connIdle`              | ۱۲۰ ثانیه         |
| `uplinkOnly` / `downlinkOnly`           | ۱ ثانیه           |
| `streamSettings.sockopt.tcpUserTimeout` | ۱۲۰۰۰۰ میلی‌ثانیه |
| `tcpKeepAliveIdle`                      | ۶۰ ثانیه          |
| `tcpKeepAliveInterval`                  | ۱۵ ثانیه          |

مقادیر صریح کانفیگ، از جمله صفر، حفظ می‌شوند. معنای صفر برای هر گزینه طبق Xray است؛ برای مثال صفر در
`tcpUserTimeout` مهلت سوکت را غیرفعال می‌کند، اما صفر در مهلت‌های نشست همان معنا را ندارد. برای
تنظیم مهلت بی‌فعالیتی، قالب کانفیگ Xray را ویرایش کنید. گزینه‌های سوکت ورودی و خروجی در فرم مربوط به
آن‌ها قابل تنظیم‌اند.

پچ کپی بافرشدهٔ آزمایشی به درخواست مالک پروژه حذف شده است و هسته از مسیر مستقیم قبلی استفاده می‌کند.
این مسیر می‌تواند `connIdle` را به ۲۴ ساعت تغییر دهد؛ بنابراین مهلت بی‌فعالیتی ۱۲۰ ثانیه برای همهٔ
مسیرهای TCP تضمین نمی‌شود. مهلت سوکت `tcpUserTimeout` مستقل از این مسیر باقی می‌ماند و برای صف TCP
تأییدنشده/پنجرهٔ بسته کاربرد دارد.

بررسی بی‌فعالیتی Xray دوره‌ای است؛ در مسیرهایی که مهلت تنظیم‌شده را رعایت می‌کنند، پیش‌فرض ۱۲۰ ثانیه
معمولاً حدود ۲ تا ۴ دقیقه طول می‌کشد؛ این زمان برای مسیر مستقیم TCP تضمین نمی‌شود. `tcpUserTimeout`
برای دادهٔ TCP تأییدنشده یا پنجرهٔ دریافت بسته کاربرد دارد؛ پُر بودن لحظه‌ای صف به‌تنهایی باعث بستن
اتصال نمی‌شود.

UDP تأیید دریافت ندارد. نشست بدون فعالیت مهلت می‌گیرد؛ اگر بسته‌ها همچنان مبادله شوند، برای تشخیص
مرده بودن کلاینت باید از heartbeat همان پروتکل استفاده کرد. سوکت شنوندهٔ UDP و حالت TCP `TIME_WAIT`
اتصال کاربرِ قابل‌حذف محسوب نمی‌شوند.

شمارندهٔ TCP صفحهٔ اصلی فقط سوکت‌های `ESTABLISHED` را می‌شمارد. شمارندهٔ UDP تعداد سوکت‌های کل
میزبان را نشان می‌دهد، نه تعداد کاربران یا نشست‌های VPN. سربرگ فایل‌های `/proc` شمرده نمی‌شود.

این تغییرات تنظیمات عمومی `sysctl` میزبان، صف شبکه و هسته‌های مستقل مانند OpenVPN/ocserv را تغییر
نمی‌دهند. تست با هستهٔ واقعی روی loopback انجام شده است: حفظ اتصال فعال TCP/UDP، بسته‌شدن سوکت خروجی
UDP پس از بی‌فعالیتی و آزادشدن صف TCP مقصدی که داده را نمی‌خواند. برای کوتاه‌شدن تست، مهلت‌های
آزمایشی یک ثانیه‌اند. وضعیت سرور واقعی باید پس از به‌روزرسانی بررسی شود.
